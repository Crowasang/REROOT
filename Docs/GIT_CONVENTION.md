# Git 컨벤션

## 브랜치

| 브랜치 | 용도 |
|---|---|
| `main` | 안정 버전. 직접 커밋하지 않고 `dev`에서만 합친다. |
| `dev` | 개발 통합 브랜치. 작업 브랜치는 항상 여기서 만든다. |
| `feat/<이름>` | 새 기능 (예: `feat/upgrade-ui`) |
| `fix/<이름>` | 버그 수정 (예: `fix/tree-hp-reset`) |
| `doc/<이름>` | 문서 (예: `doc/claude-guide`) |

- 브랜치 이름은 영어 소문자와 하이픈(`-`)만 쓴다.
- 작업 하나에 브랜치 하나. 머지한 뒤에는 브랜치를 지운다(로컬·원격 모두).

## 머지는 PR로

1. 작업 브랜치에서 커밋하고 푸시한다.
2. `dev` 대상으로 PR을 만든다. 제목은 커밋 메시지 형식, 설명에는 무엇을 왜 바꿨는지와 확인한 내용을 한국어로 쓴다.
3. 확인이 끝나면 GitHub에서 머지하고 브랜치를 지운다.

- `feat`·`fix`·`doc` 브랜치는 `dev`로만 합친다. `main`은 `dev`에서만 PR로 합친다.
- 커밋, 푸시, PR 생성, 머지는 사용자가 요청할 때만 한다.

## 커밋 메시지

```
<타입>: <한글 내용>

<본문 (선택)>
```

| 타입 | 용도 | 예시 |
|---|---|---|
| `feat` | 새 기능, 기능 변경, 에셋·밸런스 수치 변경 | `feat: 강화 화면 추가` |
| `fix` | 버그 수정 | `fix: 세션 종료 후 나무 체력이 초기화되지 않는 문제 수정` |
| `doc` | 문서 | `doc: Git 컨벤션을 PR 방식으로 변경` |

- 콜론 뒤에 한 칸 띄우고 한국어로, 마침표 없이 쓴다.
- 본문에는 **왜** 바꿨는지를 쓴다. 무엇을 바꿨는지는 diff로 보인다.
- 커밋 하나에는 작업 하나만 담는다.

## 커밋하지 않는 것

- `ProjectSettings/` 변경. 게임이 돌아가는 데 꼭 필요한 설정 변경이면 먼저 알리고, 허락받은 경우에만 따로 커밋한다.
- 아트 에셋: `Assets/_Project/Art/Varco/`, `Assets/Resources/`, 블렌더 원본 `ArtSource/` (에셋은 따로 공유한다).
- 플러그인 폴더: NuGet(`Assets/Packages/`, `packages.config`로 복원), DOTween.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `*.csproj`, `*.sln` (`.gitignore`에 포함).

## Unity 관련 규칙

- `.meta` 파일은 항상 원본 파일과 같이 커밋한다.
- 커밋하기 전에 Unity 콘솔에 에러가 없는지 확인한다.
- 씬과 프리팹은 충돌을 풀기 어렵다. 같은 씬을 여러 브랜치에서 동시에 고치지 않고, 실험은 테스트 씬에서 한다.
