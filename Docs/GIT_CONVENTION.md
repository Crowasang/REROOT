# Git 컨벤션

## 브랜치

| 브랜치 | 용도 |
|---|---|
| `main` | 배포(빌드) 가능한 상태. 직접 커밋하지 않는다. |
| `develop` | 개발 통합 브랜치. 기능 브랜치는 여기서 나와서 여기로 합친다. |
| `feature/<기능>` | 새 기능 (예: `feature/tree-chopping`, `feature/upgrade-ui`) |
| `fix/<내용>` | 버그 수정 (예: `fix/tree-hp-reset`) |
| `refactor/<내용>` | 동작 변화 없는 구조 정리 |
| `release/<버전>` | 출시 준비 (예: `release/0.1.0`). 끝나면 `main`과 `develop` 양쪽에 합친다. |

- 브랜치 이름은 영어 소문자와 하이픈(`-`)만 쓴다.
- 마일스톤(M1 버티컬 슬라이스 등)을 끝내면 `develop`을 `main`에 합치고 태그를 단다 (예: `v0.1.0`).

## 커밋 메시지

```
<타입>: <요약>

<본문 (선택)>
```

- 요약은 한국어로, 50자 안쪽, 마침표 없이 쓴다.
- 본문에는 **왜** 바꿨는지를 쓴다. 무엇을 바꿨는지는 diff로 보인다.

| 타입 | 용도 | 예시 |
|---|---|---|
| `feat` | 새 기능 | `feat: 좌클릭 벌목 구현` |
| `fix` | 버그 수정 | `fix: 세션 종료 후 나무 체력이 초기화되지 않는 문제 수정` |
| `refactor` | 동작 변화 없는 코드 정리 | `refactor: 나무 수치를 TreeData로 분리` |
| `asset` | 모델, 프리팹, 씬, 데이터 에셋 추가·변경 | `asset: 소나무 모델과 프리팹 추가` |
| `balance` | 밸런스 수치만 조정 | `balance: 3단계 나무 체력 2000 → 800` |
| `chore` | 패키지, 설정, 폴더 정리 등 | `chore: UniTask, R3 패키지 추가` |
| `docs` | 문서 | `docs: Git 컨벤션 작성` |
| `test` | 테스트 코드 | `test: 강화 비용 계산 테스트 추가` |

- 커밋 하나에는 한 가지 변경만 담는다. 코드 정리와 기능 추가는 나눠서 커밋한다.

## Unity 관련 규칙

- `.meta` 파일은 항상 원본 파일과 같이 커밋한다.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `*.csproj`, `*.sln`은 커밋하지 않는다 (`.gitignore`에 포함).
- 씬과 프리팹은 충돌을 사람이 풀기 어렵다. 같은 씬을 여러 브랜치에서 동시에 고치지 않는다.
- 내가 의도하지 않은 `ProjectSettings/` 변경(에디터가 자동으로 바꾼 것)은 따로 확인하고, 필요 없으면 커밋하지 않는다.
- 모델(FBX), 텍스처, 사운드 같은 큰 바이너리가 늘어나면 Git LFS 도입을 검토한다.
